# Character-Lock — Agent Rules

A rules-based operational system designed to eliminate dialogue attribution errors, swapped physical actions, vocal homogenization, and emotional-arc drift in multi-character AI generation across screenplays, prose narratives, and AI video prompt compilation.

---

## 1. The Multi-Character Cognitive Failure Mode

Large language models (LLMs) and diffusion prompt compilers frequently fail in multi-character dialogue through four distinct mechanical breakdown patterns:

```
┌────────────────────────────────────────────────────────────────────────┐
│             THE 4 MULTI-CHARACTER GENERATION FAILURE MODES             │
├─────────────────────────┬──────────────────────────────────────────────┤
│ 1. Content-First Drift  │ Generates emotional content before speaker   │
│                         │ assignment, causing attribution swapping.    │
├─────────────────────────┼──────────────────────────────────────────────┤
│ 2. Vocal Bleed / Blend  │ Character A adopts Character B's syntax,     │
│                         │ vocabulary, and status register mid-scene.   │
├─────────────────────────┼──────────────────────────────────────────────┤
│ 3. Future-Arc Rushing   │ Model sees the entire emotional arc and      │
│                         │ leaps to resolution beats prematurely.       │
├─────────────────────────┼──────────────────────────────────────────────┤
│ 4. Presence Hallucination│ Silent or absent characters perform actions   │
│                         │ or speak without crossing the room threshold.│
└─────────────────────────┴──────────────────────────────────────────────┘
```

This skill provides an unyielding mechanical harness to lock down identity, voice, emotional trajectory, and turn sequence.

## 2. Character ID Schema & Invariant Identity Blocks

Never rely on the model to infer who is speaking from context or narrative prose. Every active character must possess a machine-readable, persistent identity block injected into the generation prompt.

### A. The Master Identity Block Schema

```text
[CHAR:<SHORT_ID> | name:<Full Name> | ref_image:<path_or_tag> | role:<protagonist/antagonist/foil/catalyst/support> | voice:<3-5 comma-separated trait words> | current_emotion:<active-state> | arc_stage:<N of Total>]
```

### B. Production Examples
```text
[CHAR:MAYA | name:Maya Chen | ref_image:<Picture 1> | role:protagonist | voice:clipped,sarcastic,guarded,monosyllabic | current_emotion:defensive-anger | arc_stage:2of5]
[CHAR:DEV | name:Dev Okafor | ref_image:assets/dev_turnaround_sheet.png | role:foil | voice:warm,evasive,over-explaining,deferential | current_emotion:anxious-placating | arc_stage:2of5]
[CHAR:COL_VANCE | name:Marcus Vance | ref_image:pic2 | role:antagonist | voice:formal,predatory,hushed,declarative | current_emotion:cold-dominance | arc_stage:1of4]
```

### C. Operational Rules for ID Blocks
1. **Fixed SHORT_ID:** The identifier (e.g., `MAYA`, `DEV`, `RICK`, `NEIL`) is locked for the entire project lifecycle. Never alias, shorten, or change case.
2. **Active Presence Filtering:** Only include ID blocks for characters physically present and conscious in the active beat. If a character is off-screen or silent, **omit their block completely**. Carrying silent characters forward invites presence hallucinations.
3. **Dynamic State Refreshing:** The `current_emotion` and `arc_stage` values must be refreshed with current beat parameters, never copy-pasted with stale values from Scene 1.
4. **Context Re-Injection Interval:** In extended dialogue sequences (>10 lines), re-inject the ID blocks every 3–4 turns to counteract attention dilution.

### D. Reference Image Binding & Multimodal Continuity
The `ref_image` field bridges textual dialogue generation with visual diffusion models:
1. **Visual Asset Anchoring:** Binds the character to a concrete visual file path (`assets/maya_turnaround.png`), multimodal tag (`<Picture 1>`), or model asset slot (`pic0`).
2. **Somatic Action Grounding:** Action beats (`ACTION:`) can directly reference visual specifics established in the image (e.g. *"tugs at the silver ear cuff visible in <Picture 1>"*, *"pulls up the collar of the charcoal trench coat"*). This prevents the model from inventing contradictory physical props or apparel mid-scene.
3. **Automated Video Compiler Bridge:** When a screenplay is compiled into MiniMax H3, Kling, or Midjourney prompts via [`ai-video-storytelling`](file:///c:/Users/Desktop-Dev/Desktop/technical%20vocabulary%20%20nomalizer/.agents/skills/ai-video-storytelling/SKILL.md), the compiler automatically routes the `ref_image` target into the diffusion engine's image-conditioning reference slot.
4. **Integration with `character-reference-sheet`:** Pairs directly with model sheets generated by [`character-reference-sheet`](file:///c:/Users/Desktop-Dev/Desktop/technical%20vocabulary%20%20nomalizer/.agents/skills/character-reference-sheet/SKILL.md) (front/profile/back turnaround, expression strip, feature guards), ensuring the 4-panel sheet serves as the immutable single source of truth across all 60+ episodes.

## 3. Line Structure: Enforced Speaker-Before-Content Ordering

The single largest cause of attribution errors is prose-first generation, where the model drafts an emotionally charged line and retroactively assigns a character name. 

Attribution must be decided and locked **before** content generation occurs.

### A. The Strict 3-Slot Line Grammar
Every line of dialogue and physical action must strictly adhere to this format:

```text
SPEAKER: [CHAR:<SHORT_ID>]
ACTION: <Concrete physical beat, posture, or somatic micro-kinetic direction>
LINE: "<Verbatim dialogue text>"
```

### B. Correct vs. Incorrect Formatting

#### ❌ Incorrect (Prose/Paragraph Format — Prone to Swapping):
```text
Maya turned toward the window, her jaw tight. "I told you never to contact him."
Dev smiled anxiously, rubbing his neck. "I didn't have a choice, Maya."
"There's always a choice!" Dev shouted angrily, slamming his coffee down.  <-- ATTRIBUTION SWAP BUG!
```

#### ✅ Correct (Enforced Line Structure):
```text
SPEAKER: [CHAR:MAYA]
ACTION: Turns head 45 degrees toward rain-slicked window, jaw muscles flexing under pale skin.
LINE: "I told you never to contact him."

SPEAKER: [CHAR:DEV]
ACTION: Shifts weight onto heels, right hand nervously rubbing nape of neck.
LINE: "I didn't have a choice, Maya."

SPEAKER: [CHAR:MAYA]
ACTION: Slams white ceramic mug onto Formica table with a sharp crack; pupils locked on Dev.
LINE: "There is always a choice."
```

## 4. Decoupled Emotional Journey (State Machine Engine)

Characters must not determine their emotional reactions purely from the immediately preceding line of dialogue. When emotional state is unanchored, conversations devolve into rapid, unearned polarity flips or homogeneous agreement.

### A. The Standalone Arc Data Structure
Define each character’s emotional arc as an independent, deterministic state machine decoupled from scene prose:

```python
MAYA_ARC = {
    "start": "guarded-neutral",
    "beat1": {
        "state": "defensive-anger",
        "trigger": "Dev's evasive answer regarding the money"
    },
    "beat2": {
        "state": "suppressed-hostility",
        "trigger": "Refusal to take the bait; holding tactical boundary"
    },
    "beat3": {
        "state": "cracked-vulnerability",
        "trigger": "ENVIRONMENT INTERRUPT: Sirens wailing in alleyway below"
    },
    "resolution": {
        "state": "wary-openness",
        "trigger": "Dev hands over the unsealed ledger"
    }
}
```

### B. The 2-Beat Context Window Rule
* **Never pass the full future arc into the generation prompt.** If the model sees that Maya ends in `"wary-openness"`, it will soften her dialogue in Beat 1.
* **Pass only:** 
  1. The *Current Beat State* (target destination).
  2. The *Immediate Previous Beat State* (launch point for contrast).

```text
[MAYA ARC CONTEXT: Moving from 'defensive-anger' (Beat 1) into 'suppressed-hostility' (Beat 2). Do NOT allow vulnerability or reconciliation in this beat.]
```

### C. Environment-Reactive Arc Triggers
Tie emotional pivots directly to physical and environmental events (the core workspace storytelling principle). Emotional changes must be triggered by:
- An outside arrival (a third party entering).
- A somatic catastrophe (a dropped glass, spilled blood, a stall in breathing).
- A digital/broadcast rupture (a phone notification pinging with a critical balance alert).

## 5. Turn-Locking Protocol for Multi-Character Exchanges

For high-stakes confrontations, comedy status reversals, or tense negotiations, use **Turn-Locking** to eliminate cross-character contamination.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        TURN-LOCKING CYCLE                              │
├────────────────────────────────────────────────────────────────────────┤
│ Step 1: Isolate Speaker A → Prompt with only A's ID block & beat state.│
│ Step 2: Generate A's Turn (SPEAKER + ACTION + LINE).                   │
│ Step 3: Freeze A's Turn as immutable read-only context.                │
│ Step 4: Isolate Speaker B → Feed A's verbatim output; prompt with B's  │
│         ID block & beat state.                                         │
│ Step 5: Generate B's Turn (SPEAKER + ACTION + LINE).                   │
└────────────────────────────────────────────────────────────────────────┘
```

By generating one character's turn at a time, the model cannot accidentally bleed Speaker B's syntax into Speaker A's vocabulary.

## 6. Critique-Mode Consistency Audit (Pass/Fail Gates)

After any multi-character scene is generated, run a dedicated audit pass. If any gate fails, **regenerate only the offending line**, never the entire scene (regenerating whole scenes introduces new drift).

| Audit Gate | Pass Condition | Failure Mode (Regenerate Line) |
| :--- | :--- | :--- |
| **1. Voice Trait Match** | Vocabulary and sentence length match the 3–5 trait words in the character's ID block. | A laconic, cynical character suddenly delivers a three-clause flowery explanation. |
| **2. Arc-State Alignment** | Emotional valence precisely reflects the character's *current* arc stage, not the scene average. | Character displays softness or forgiveness before their arc trigger has fired. |
| **3. Presence & Spatial Check** | Character performing the action was tagged as physically present in the room beat. | A character who left the room two beats ago suddenly hands someone a coffee. |
| **4. Role Integrity Check** | Dialogue serves the character's core structural role (Protagonist, Foil, Antagonist). | Antagonist speaks with the moral perspective or rhetorical style of the hero. |
| **5. Order Validation** | Every line strictly obeys `SPEAKER` $\to$ `ACTION` $\to$ `LINE`. | Line begins with dialogue quotes or freeform script prose. |

## 8. Quick Failure Troubleshooting Checklist

If attribution swapping or vocal drift occurs during generation, run down this checklist immediately:

- [ ] **Are ID blocks missing?** Check if context length pushed earlier ID blocks out of memory. *Remedy: Re-inject ID blocks directly above the active prompt.*
- [ ] **Are voice traits too similar?** If two characters are both labeled *"cynical, intelligent, quiet"*, they will bleed together. *Remedy: Sharpen contrast (make Character A "cynical, monosyllabic, gravelly" and Character B "hyper-verbal, manic, academic").*
- [ ] **Are emotional arc beats too tightly packed?** If Beat 1 is *"annoyed"* and Beat 2 is *"irritated"*, the model cannot differentiate. *Remedy: Widen the emotional delta (e.g., "stony silence" $\to$ "explosive rage").*
- [ ] **Did prose precede speaker attribution?** *Remedy: Enforce `SPEAKER: [CHAR:<ID>]` at the absolute start of the output line.*
